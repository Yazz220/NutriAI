# Apple App Store first-submission checklist

Checked against Apple's published requirements on 2026-08-26. This is a launch checklist for the current Folio iOS app, not a general legal opinion. Apple changes the rules and review practice, so recheck the linked pages on submission day.

## Verified release evidence — 2026-08-26

- EAS production build 11 (`f1ae66c4-ecf8-41a5-86c3-7f268e22aca0`) finished successfully for Folio 1.0.0. The build used Xcode 26.0 (17A324) and the iOS 26.0 SDK on macOS Sequoia 15.6.
- The exported IPA was inspected directly. Its root privacy manifest declares no tracking; name, email address, photos/videos, other user content, and user ID; and the aggregated required-reason API declarations for user defaults, file timestamps, disk space, and system boot time. All 14 packaged privacy manifests parse as valid property lists.
- No packaged `Info.plist` contains `NSMicrophoneUsageDescription`. Camera and photo-library purpose strings remain for explicit recipe-capture actions.
- Signed Mach-O entitlements were inspected for both targets. `com.yaz12.nosh` includes Sign in with Apple and `group.com.yaz12.nosh.share`; `com.yaz12.nosh.share` includes the same App Group. Both use App Store profiles with `get-task-allow` set to `false` and expire on 2027-02-21.
- The build log contains no matched warning or error lines and confirms that the IPA was exported and signed successfully.
- GitHub Pages is enabled from this branch's `/docs` directory. The configured [privacy policy](https://yazz220.github.io/NutriAI/privacy.html) and [support page](https://yazz220.github.io/NutriAI/support.html) both return HTTP 200 over HTTPS.
- This Windows/EAS audit does not replace Xcode Organizer's **Generate Privacy Report** action. Run that action from the exact archive on macOS before submission, or use App Store Connect's validation feedback after upload.

## Current Folio findings

The following items come from a focused inspection of `app.json`, authentication and account-deletion code, and the launch-facing UI. They should be resolved before the first production submission.

- [x] **Build with Xcode 26 or later and the iOS 26 SDK.** Production build 11 used Xcode 26.0 and the iOS 26.0 SDK. [Apple's current SDK minimum](https://developer.apple.com/news/upcoming-requirements/)
- [x] **Add an in-app privacy policy link and publish the same policy at a stable public URL.** Settings links to the live HTTPS privacy policy and support pages. The policy covers collected data, purposes, AI recipients, retention, deletion, consent withdrawal, and contact paths. The same URLs are ready for App Store Connect. [Guideline 5.1.1](https://developer.apple.com/app-store/review/guidelines/)
- [x] **Add explicit consent before first use of external AI processing.** Folio now explains what is sent, why it is sent, and that OpenRouter and selected model providers process the content before the first AI-backed action. The disclosure links to the privacy policy and stores a versioned consent decision. [Guideline 5.1.2(i)](https://developer.apple.com/app-store/review/guidelines/)
- [x] **Finish Sign in with Apple deletion.** The deployed `delete-account` flow now revokes the Apple refresh token server-side before deleting Supabase authentication, database, and storage data. The Apple signing key and identifiers are stored as Edge Function secrets rather than client configuration. A production end-to-end deletion test remains in the Accounts section below. [Account-deletion guidance](https://developer.apple.com/support/offering-account-deletion-in-your-app/)
- [ ] **Generate and inspect the privacy report from the exact release archive.** The exported build 11 IPA has been manually inspected: all 14 packaged manifests parse, the root manifest contains the expected collection disclosures, and required-reason declarations are aggregated. Xcode Organizer's generated privacy report still needs to be reviewed on macOS before submission. [Third-party SDK requirements](https://developer.apple.com/support/third-party-SDK-requirements/), [privacy report procedure](https://developer.apple.com/documentation/bundleresources/describing-data-use-in-privacy-manifests), and [required-reason APIs](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api)
- [x] **Remove the microphone permission unless voice input ships in version 1.0.** The iOS purpose string, Android `RECORD_AUDIO` permission, and camera/image-picker microphone configuration have been removed. The signed IPA contains no microphone usage-description key. [Guideline 5.1.1(iii-iv)](https://developer.apple.com/app-store/review/guidelines/)
- [x] **Keep generated recipe artwork private.** The `cookbook-pages` bucket is private, stored page references are storage object paths rather than public URLs, and clients resolve short-lived signed URLs only for authenticated users. A migration handles existing public URL references.
- [x] **Add AI safety and a report path.** The production migration and Edge Functions are deployed. Folio rejects clear intentional harm, self-harm, sexual-content, and malicious non-cooking requests before model processing; ignores client-supplied system messages; adds conservative food-safety and allergy rules to the server prompt; and provides an accessible Report action backed by a private service-role-only table. A report sent from TestFlight build 13 was verified in production at `2026-08-26 02:28:32 UTC` with status `open` and a valid owner. Apple places chatbots under guideline 4.7 and makes the app developer responsible for offered software and content. Explain in review notes that cookbooks and conversations are private and users cannot publish to or message other users. [Guideline 4.7](https://developer.apple.com/app-store/review/guidelines/)
- [ ] **Document content rights for recipe imports.** The [content-rights memo](CONTENT_RIGHTS_2026-08.md) establishes that App Store Connect must be set to **Yes, this app uses third-party content** (`USES_THIRD_PARTY_CONTENT`). Ordinary imports must retain the source link and normalize recipe facts without reproducing source media or expressive editorial content. Build 13 still sends YouTube, TikTok, and Instagram video URLs to an AI provider for extraction, but those platforms do not grant this workflow permission in their public terms. Disable social-video extraction before App Review or obtain explicit authorization, then require users to confirm rights to uploaded media. [Guidelines 5.2.1-5.2.3](https://developer.apple.com/app-store/review/guidelines/)

## Privacy manifests, permissions, and App Privacy

- [ ] Archive in Xcode, then use Organizer's **Generate Privacy Report** action. Compare the aggregated report with the app's actual code, Expo modules, React Native/Hermes, Supabase, and every other packaged SDK. [Generate a privacy report](https://developer.apple.com/documentation/bundleresources/describing-data-use-in-privacy-manifests)
- [ ] Verify every SDK on Apple's required list contains a valid privacy manifest and, for binary SDKs, the required signature. App Store Connect rejects invalid manifests. [Adding a privacy manifest](https://developer.apple.com/documentation/bundleresources/adding-a-privacy-manifest-to-your-app-or-third-party-sdk)
- [x] Declare an approved reason for every covered API used by app or SDK code. The build 11 aggregate contains user-default reasons `CA92.1` and `1C8F.1`, file-timestamp reasons including `C617.1`, disk-space reasons `E174.1` and `85F4.1`, and system-boot-time reason `35F9.1`. [Required-reason APIs](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api)
- [ ] Complete App Privacy answers for Folio and its third parties. Based on current behavior, audit at least email address, user ID, photos or videos, other user content such as recipes and chats, and any usage or diagnostic data retained by Supabase, model providers, logging, or SDKs. Data stored under an account will normally be "linked to the user." State "not used for tracking" only after confirming no party links app data with third-party data for advertising or measurement. [App Privacy definitions](https://developer.apple.com/app-store/app-privacy-details/) and [App Store Connect procedure](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy/)
- [ ] Make the App Privacy answers, privacy manifest, privacy policy, consent screens, system purpose strings, backend logging, provider retention settings, and deletion behavior agree. Apple requires answers to cover third-party partners and stay current.
- [ ] Confirm Folio does not access IDFA or track users. If tracking exists, implement App Tracking Transparency before tracking occurs. If it does not, do not display an ATT prompt. [Apple user privacy and data use](https://developer.apple.com/app-store/user-privacy-and-data-use/)
- [ ] Prefer the system picker and share sheet over broad photo-library access. Verify camera and photo access are optional paths and that text/URL intake still works when the user declines them. [Guideline 5.1.1(iii-iv)](https://developer.apple.com/app-store/review/guidelines/)

## Accounts and Sign in with Apple

- [ ] Confirm email/password sign-up, email/password sign-in, password reset, Sign in with Apple, sign-out, and session restoration work against production.
- [ ] Keep Sign in with Apple as an equivalent option if any other social or third-party primary-account login is offered. Email/password by itself does not trigger guideline 4.8. The current Apple option is appropriate. [Guideline 4.8](https://developer.apple.com/app-store/review/guidelines/)
- [ ] Request only Apple data the app uses. The current flow asks for full name and email, then stores the name. If the product never displays or uses a name, remove the full-name scope and stored field to meet data-minimization expectations.
- [ ] Make deletion available in Settings without requiring an email or support call. It must delete the account, cookbooks, RecipeGraphs, capture sources, generated page art, chat threads/messages, caches, and any other associated data unless law requires retention. State the retention exception and timing if one exists. Deactivation alone is not enough. [Apple account-deletion requirements](https://developer.apple.com/support/offering-account-deletion-in-your-app/)
- [ ] Test deletion for both password and Apple-created accounts. Confirm Apple token revocation, Supabase authentication deletion, database cascades, both storage buckets, conversation storage, local cache cleanup, and inability to reuse the old session.
- [ ] Explain in review notes why an account is integral to the persistent cloud cookbook. Apple asks apps without significant account-based features to work without login. [Guideline 5.1.1(v)](https://developer.apple.com/app-store/review/guidelines/)

## AI, user content, safety, and age rating

- [ ] Keep the product and metadata framed as a personal cookbook with a conversational chef. Do not market it as medical, dietetic, allergy-safe, or clinically accurate unless the product and evidence support those claims. Medical claims receive extra scrutiny. [Guideline 1.4.1](https://developer.apple.com/app-store/review/guidelines/)
- [ ] Test guardrails against unsafe temperatures, poisonous ingredients, severe allergy substitutions, eating-disorder prompts, drug or alcohol encouragement, sexual content, hate, violence, and instructions outside the cookbook scope. Give users a clear reminder to use judgment for allergies and food safety. This is a product-safety recommendation grounded in Apple's developer responsibility for chatbot content and physical-harm rules. [Guidelines 1.4 and 4.7](https://developer.apple.com/app-store/review/guidelines/)
- [ ] If content remains private to one account, answer the age-rating "User-Generated Content" and "Messaging and Chat" capabilities based on Apple's definitions. Those definitions concern broad distribution and users communicating with one another, which Folio currently does not provide. If public sharing, discovery, comments, or user-to-user chat is added later, update the rating and implement filtering, reporting, timely response, blocking, and published contact information before release. [Age-rating definitions](https://developer.apple.com/help/app-store-connect/reference/app-information/age-ratings-values-and-definitions) and [Guideline 1.2](https://developer.apple.com/app-store/review/guidelines/)
- [ ] Answer the current age-rating questionnaire, including any alcohol references or wellness information the assistant can produce. The updated questionnaire has applied since 2026-01-31, and an Unrated app cannot publish. Do not choose "Made for Kids" unless the app is intentionally built to satisfy the permanent Kids Category rules. [Set an app age rating](https://developer.apple.com/help/app-store-connect/manage-app-information/set-an-app-age-rating)

## Payments and subscriptions

The current project documentation says generation credits are suspended and the client has no active purchase path. A free version 1.0 with no IAP is the lowest-risk submission.

- [ ] Confirm there is no purchase button, external checkout call-to-action, paywall, license key, paid web entitlement, or dormant credit balance presented in version 1.0.
- [ ] If paid AI generations, premium cookbook features, digital credits, or a subscription ship, use StoreKit In-App Purchase unless a precise Apple exception applies. Digital features consumed in the app generally must use IAP. [Guideline 3.1.1](https://developer.apple.com/app-store/review/guidelines/)
- [ ] For restorable purchases, provide Restore Purchases. Purchased credits may not expire.
- [ ] For subscriptions, provide ongoing value across the user's devices and show the subscription name, duration, included service, full renewal price, trial terms, and a restore/sign-in route before purchase. Link Terms of Use and Privacy Policy in both the app and metadata. [Apple subscription requirements](https://developer.apple.com/app-store/subscriptions/) and [Guideline 3.1.2](https://developer.apple.com/app-store/review/guidelines/)
- [ ] Create complete IAP metadata and review screenshots. Submit the first subscription with a new app version and explain how the reviewer reaches the paywall and tests purchase and restore. [Offer auto-renewable subscriptions](https://developer.apple.com/help/app-store-connect/manage-subscriptions/offer-auto-renewable-subscriptions/)
- [ ] If a subscription exists, warn during account deletion that Apple billing continues until the user cancels and provide the system subscription-management path. Account deletion must still be available immediately. [Account deletion with subscriptions](https://developer.apple.com/support/offering-account-deletion-in-your-app/)

## Product page and App Store Connect record

- [ ] Create or verify the app record, primary language, bundle ID, SKU, app name, subtitle, primary category, optional secondary category, and Content Rights response. A name is 2-30 characters and a subtitle is at most 30. [App information reference](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information)
- [ ] Write an accurate plain-text description of at most 4,000 characters and keywords totaling at most 100 bytes. Do not advertise audio intake, a table of contents, review/approval steps, credits, or any other retired or dormant behavior. [Platform version information](https://developer.apple.com/help/app-store-connect/reference/app-information/platform-version-information) and [Guideline 2.3](https://developer.apple.com/app-store/review/guidelines/)
- [ ] Provide a working Support URL with a visible way to contact the developer. A Marketing URL is optional. Use the privacy URL described above. [Guideline 1.5](https://developer.apple.com/app-store/review/guidelines/)
- [ ] Choose the price or free tier, tax category, storefront availability, and release method. For a first release, manual release gives a useful final checkpoint after approval. Apple requires pricing and availability before publishing. [Publishing workflow](https://developer.apple.com/help/app-store-connect/manage-your-apps-availability/overview-of-publishing-your-app-on-the-app-store)
- [ ] Declare Digital Services Act trader status even if the app will not ship in the EU. If it will ship there and the developer is a trader, verify the address, phone, and email Apple displays publicly. [DSA trader requirements](https://developer.apple.com/help/app-store-connect/manage-compliance-information/manage-european-union-digital-services-act-trader-requirements)
- [ ] Complete copyright, app-review contact details, privacy answers, age rating, export compliance, version release settings, and all other required fields shown by App Store Connect. [Required properties](https://developer.apple.com/help/app-store-connect/reference/app-information/required-localizable-and-editable-properties)

## Review access

- [ ] Create a non-expiring production demo account with enough seeded data to demonstrate the shelf, a finished cookbook page, import history, chat history, and account settings. Do not use a real person's data.
- [ ] Provide App Review contact name, email, and an international-format phone number. If login is required, username and password are required review fields and the account must not expire. [App Review information fields](https://developer.apple.com/help/app-store-connect/reference/app-information/platform-version-information)
- [ ] Keep email verification, rate limits, model quotas, and anti-abuse systems from blocking the reviewer. If a one-time code is unavoidable, give Apple a reliable way to obtain it. A durable password demo account is simpler.
- [ ] Write concrete review notes that explain: Folio is a private cookbook; how to open a book; how to import a text or URL recipe without granting Photos; how photo import works; that capture and page generation are asynchronous; how to open and use the persistent chef; where AI consent appears; where to report a response; where to delete the account; and that no IAP ships in version 1.0. Apple asks for full access, live backends, and explanations of non-obvious features. [Before You Submit](https://developer.apple.com/app-store/review/guidelines/)
- [ ] Exercise the entire reviewer script on a clean production build using only the supplied notes and credentials.

## TestFlight and submission sequence

- [ ] Upload the production candidate and resolve processing, privacy-manifest, export-compliance, entitlement, and signing warnings before inviting testers.
- [ ] Run an internal TestFlight pass with App Store Connect users, then an external pass on a representative set of devices and iOS versions. TestFlight builds expire after 90 days. Apple allows up to 100 internal testers and 10,000 external testers; the first external build may require beta review. [TestFlight overview](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview)
- [ ] Test account creation, Apple and password login, deletion, recipe capture from every source, destination selection, retries, offline recovery, page generation, reader gestures, export/share, accessibility basics, notification-free operation, and all permission-denied paths.
- [ ] Triage every crash and verify the final candidate again after the last change. Do not submit a TestFlight-only or beta-labeled experience to the App Store. [Guidelines 2.1-2.2](https://developer.apple.com/app-store/review/guidelines/)
- [ ] In App Store Connect, select the processed build, finish required metadata and compliance items, choose **Add for Review**, inspect the draft submission, then choose **Submit for Review**. [Submit an app](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-app)
- [ ] Watch App Review messages and respond with exact reproduction steps or a corrected build. After approval, Apple says availability can take up to 24 hours. [Publishing workflow](https://developer.apple.com/help/app-store-connect/manage-your-apps-availability/overview-of-publishing-your-app-on-the-app-store)
